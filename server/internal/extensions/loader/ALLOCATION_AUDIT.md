# Complete-loader allocation audit

Gate B is pending. The YAML path has a pre-allocation ledger. The complete loader has an allocation envelope, not an allocator interceptor or a hard process limit. Source investigation identifies native-map directory growth and reader-error formatting that violate that envelope. Reviewed remediation and the unresolved inequalities below block source-bound approval of this candidate.

## Observation boundary

`yaml.go` contains one conversion body, `decodeVerifiedYAMLAccounted`, and one call to `yamltokens.DecodeAccounted`. The legacy wrapper delegates once and discards two scalar usage values. Inspection, duplicate detection, mapping guard and conversion retain the same parser ledger. Every error returns a nil map and a snapshot after the last attempted reservation. There is no closure, defer, interface boxing, observer or formatting helper in this wrapper. `usageYAML` returns two uint64 values by value.

Go 1.27.1 Linux amd64 escape output reports `usageYAML` and `Budget.Usage` inlineable, their budget pointers nonescaping, and the legacy converter inlineable. The sole `&Budget{}` still escapes through the parser, as it did before the adapter change. There is no additional descriptor allocation or new source growth site. The existing once-only entry charge covers this same 64-byte ledger. Native compiler behavior on Windows x64 and macOS ARM64 still needs renewed review/evidence.

## YAML ledger and conversion proof

The [parser audit](internal/yamltokens/ALLOCATION_AUDIT.md) owns scanner, reader, lookahead, resolver, exact Node/Content arenas, strings, abandoned storage and fixed entry costs. All these charges survive failures through `DecodeAccounted`. The ledger checks 64 MiB and 1,000,000 objects before each reached allocating family; failed reservations change neither counter.

Unchanged `tree.go` continues that ledger through these families:

| Family | Source bound before allocation |
|---|---|
| Profile inspection | Two rounded 416-byte walk/copy objects. Walk depth is 17 slots, not an input-sized stack. UTF-8 and unsigned integer recognizers use fixed locals. |
| Duplicate detection | Three rounded walk/copy objects, a rounded 24-byte slice header, and one exact `16*largestMappingArity` string-header backing. The inspected tree bounds the largest arity by 32,767. Sorting reuses the backing and recurses on the smaller partition, at most 15 frames. No key byte copy or hash map is made. |
| Mapping guard | Two rounded walk/copy objects. Complete profile and duplicate passes precede the guard. Every mapping is limited to 896 pairs before any output container exists. |
| Conversion stack | One rounded 512-byte array of sixteen 32-byte frames. Traversal is iterative. |
| Native maps | For zero pairs, round 48 bytes. For one to eight pairs, add a rounded 264-byte group. For nine to 896 pairs, add rounded 8-byte directory, 32-byte table and `264*c/8` group backing, where c is the smallest power of two at least `floor(8*n/7)`, at most 1,024. Exactly n distinct inserts cannot split this table for any seed. The pinned runtime/compiler proof and layout sources are in `tree.go` and spec section 4.3. |
| Sequences | Round exact `16*n` backing and a 24-byte interface slice-header box separately, including empty sequences. |
| Scalar interfaces | Charge 64 bytes and one object before each scalar; string/json.Number headers share immutable Node string bytes, bool uses static storage. |
| Helpers/errors | Static comparisons and sentinels, fixed assertions, unsigned recognition and UTF-8 checks allocate nothing. No reflection decode, alternate parse, formatting or serialization occurs in conversion. |

`yamlAllocation` bounds small objects by `2*s+32` and large objects by `s+8192`. Reservations include fixed objects even when the compiler keeps them on the stack. The adapter does not change these source limits. Stack growth is separately measured, with an unchanged 8 MiB ceiling. Maximum valid manifest presentations and all small-map/table transitions remain in the corpus.

## Full Load family inventory

Let F be the effective listed-file cap, T = F + 8 MiB, C = T + 1 MiB, A be the bytes actually received, E <= 2 MiB be envelope bytes, B <= 1 MiB be authenticated YAML bytes, and M <= 4,098 be regular members. The acceptance envelope is exactly `4*C + 4*T + 128 MiB`. No YAML allowance is added to it.

| Family and source | Established bound or reachability |
|---|---|
| Snapshot, `frame.go:readSnapshot` | Each backing is charged in cumulative reasoning, including abandoned arrays. Capacities start at 32 KiB, double, and end at the checked C+1 clamp. Summing the actual sequence gives less than `3*(C+1)` logical bytes; the final clamp is a separate term. At most 17 backings reach the hard F cap. Rounded large pages add at most 8 KiB per backing. The 32 KiB read chunk is fixed. A failing source eagerly formats the I/O cause with fmt.Errorf. Its loader-owned text copy is unbounded; a reviewed cause-preserving wrapper is required. |
| Archive copy, `loader.go` | One independent clone of A <= C bytes only after every stage succeeds. Large rounding adds at most one page. This combines with snapshot storage inside `4*C` plus separately counted small rounding overhead. |
| Frame parsing, `frame.go:frameSize` | Fixed locals and bounded offset walks allocate no input-sized storage. One frame, explicit size <= T, window <= 8 MiB and no dictionary precede the decoder. |
| Decoder setup, zstd v1.20.1 `decoder.go:88-132` | One Decoder/options, one blockDec/frameDec, capacity-one channel, empty dictionary map and CRC state. `NewReader(nil)` returns before `Reset`; streaming channels/context/goroutines are unreachable. `DecodeAll` is synchronous and `Close` runs on success/failure. Cold `initPredefined` and dependency pools remain reachable and must be counted, not warmed or subtracted. |
| Output/history, zstd `decoder.go:353-448`, `framedec.go:333-390`, `blockdec.go:228-265` | The declared output backing is allocated once by the loader, capacity <= T. With limitToCap, DecodeAll and frame-level reserve expansions are unreachable. Synchronous history aliases output. Raw/RLE append and the zero-sequence compressed path can still grow output before the later length disagreement rejects the frame. The failed final block is <= 128 KiB. This growth and its rounded abandoned backing belong in the full bound. |
| Decoder scratch, zstd `blockdec.go:189-209,361-434,481-508` | ByteBuf input makes copied `dataStorage` unreachable. One block destination is bounded by 128 KiB. Literal backing capacity is monotonically increased, max 128 KiB+16; each prior backing remains cumulative allocation. `decodeCompressed` calls `decodeSync`; the asynchronous sequence vector at `decodeSequences:655` is unreachable. FSE decoders contain fixed 512-entry tables; Huffman tables, cold pools and setup helpers still need cumulative bounds. |
| Physical tar, `tar.go` and Go 1.27.1 `archive/tar/reader.go:355-428` | M headers, bounded raw text conversions, at most 240-byte names, and at most 120 path segments per name. `portableMember` allocates the Split header backing. Each checked regular header reaches one Reader/Header and bounded standard USTAR text parsing. PAX/GNU/sparse maps, extension reads, links and body copies are unreachable. Member capacities are `16,...,4096,4098`; their cumulative backing is 12,274 40-byte slots, before rounding. Duplicate/prefix comparisons allocate nothing. |
| Envelope preflight, `envelope.go` and Go `encoding/json/v2_stream.go` and `encoding/json/jsontext` | Depth <= four; the fifth opener may grow Token's own stack once before rejection. Complete token walk has no generic map/slice tree. Scalar Token calls allocate interface cells, decoded strings/numbers and escape scratch; decoder buffers grow cumulatively. E bounds consumed bytes but does not itself bound allocator bytes to E. Dense tiny-token failures must be counted. |
| DSSE, `signing/dsse/parse.go`, `pae.go`, `dsse.go` | JSON validity, UTF-8/surrogate validation, closed root/signature fields and duplicate rejection precede base64. All accepted root payload strings are preflight-bounded. DecodeString output capacity can exceed B by two padding bytes. Canonical re-encoding allocates bytes and strings for payload/signature. PAE makes one bounded payload-plus-fixed-prefix backing. Ed25519/SHA helper state and raw error construction remain source families. Rejected multiple-signature arrays can cause many token calls, but never reach YAML. |
| YAML | The entire same-call ledger above, inclusive of failures, <= 64 MiB and 1,000,000 objects. This is part of the full envelope. |
| Manifest validation, `manifest/{tree,fields,relations,metadata}.go` | Tree/profile checks establish concrete types and <=65,536 nodes; shape rejection precedes field serialization. `fields` calls `encoding(v)` before child fields: `tree.go:71` uses json.Marshal and a byte-to-string copy for array uniqueness. Nested arrays serialize descendants repeatedly. `fields` makes hinted seen maps; relations makes names/listing/owners/own/used maps only after every field succeeds. Shapes bound components/files/capabilities; invalid scalar lexemes can be serialized before field rejection. Regex pools, URL/netip helpers, sort-key buffers, cold JSON encoder cache and error wrappers require bounds. |
| Commitments/result, `loader.go` | Body slice <=4,096 entries; commitment backing <=4,096 80-byte File records. Hex strings are checked by validation before decoding into fixed hashes. Sorting has one fixed reflection/callback setup per slice and bounded recursion. Fingerprint strings total bounded fixed bytes. File clones sum <= F logical bytes; per-object rounding, the manifest <= B clone and envelope <= E clone count separately. There is no output copy on any failure. |

After the identified defects are remediated, the object proof must combine bounded snapshot growth, M bounds tar helpers, E bounds envelope token count, YAML has its object ledger, schema/cardinality bounds validator work and F/listed count bounds copies. A reviewed numerical full-object bound and exact complete dependency-stack proof are still open. Full-call raw object/stack values remain evidence, not pass/fail ceilings invented by this harness.

## Open source inequalities

The following precise obligations are not resolved by the finite passing smoke run:

1. Bound cumulative zstd literal backing allocations at `blockdec.go:367,399,432`, including each 16-byte over-allocation and Go allocator page/size-class rounding, by successful decoded bytes plus a fixed failed-block term. Capacity monotonicity alone gives a loose quadratic maximum in the 128 KiB block cap. Combine it with actual prior-block output and the one terminating failed block, and bound cold Huffman/FSE pool/setup helpers. Combine preallocated output, possible final failed output growth, scratch, and success-only file clones inside `4*T` plus a defensible fixed term.
2. Bound raw JSON Token allocator bytes/objects through the active `encoding/json/v2_stream.go`, `encoding/json/v2` and `encoding/json/jsontext` sources across both loader preflight and DSSE `readFields/readSignature`. Partition dense-token failures that cannot reach YAML from closed one-signature success paths. A maximum preflight failure and maximum YAML/validator path cannot simply be summed as simultaneously reachable work.
3. Bound `manifest.fields` repeated `encoding(v)` at `fields.go:182` / `tree.go:71`, including Marshal's geometric buffers, result/string copies, map-key sorting, encoder cache, fields' seen maps and regex helpers. Use schema array ancestry and the aggregate text/node caps, including an invalid late scalar serialized before rejection; bound every allocation on the failure path too. Combine that bound with DSSE/YAML and tar fixed overhead in the unchanged 128 MiB term.
4. Confirm pinned runtime/compiler helper and full-stack source reasoning on each required target. Linux compiler escapes and sampled stacks do not establish Windows/macOS bounds.

Two source-derived counterexamples are established: manifest validator sets can force excessive native-map directory allocation, and archive reads eagerly format an arbitrarily long caller error. Neither was an observed end-to-end budget overflow. Their reviewed remediation is pending. No raw budget failure occurred in the finite local corpus. The remaining inequalities are proof obligations, not permission to widen budgets or change production stages. Independent review must resolve them before Gate B acceptance.

## Measurement and evidence scope

The harness measures combined conversion, same-call assembled conversion through a per-call closure with real validation, and exported `Load` without a closure. Every accepted/rejected interval uses its own raw counters. No subtraction, extra allowance, warmup, retry or sample selection occurs. Serial/two-call runs restore normal scheduling and keep normal GC; ownership mutations happen after measurement. Native RSS uses the existing OS-specific Gate A helpers on all three supported hosts, and failures fail the child.

Linux finite smoke passes. Native Gate A renewal, Gate B extended measurements, race/timed fuzzing, exact-head CI receipts and independent adversarial review are pending. Candidate source changes do not extend old Gate A approval to this adapter.
