## Claude Code specifics

- Claude does design and research only, on Fable through `.claude/agents/designer.md`. When Fable reaches its usage limit, a Codex Astra (`gpt-6-astra`, `high`) general-purpose worker writes and improves the design instead. Agents may delegate bounded tasks to subagents or general-purpose agents. There is no separate researcher role. Set the model and effort explicitly on every dispatch. Sonnet and Opus are not used in this project.
- No review and no implementation runs on a Claude model. Sol xhigh or Astra xhigh reviews designs and code, whichever is free, never work the same model wrote, so Astra reviews Sol's code and Sol reviews Astra's designs (`instructions/workflow.md`). Implementation runs on Sol medium. The definitions are in `.codex/agents/`; Astra design work uses a general-purpose worker. From a Claude Code session, run Codex tasks through the plugin's companion script `task` command with `--model` (`gpt-6.1-sol` or `gpt-6-astra`) and `--effort` set explicitly; the plugin's `review` command only covers git diffs. A reviewer never implements what they review.
- Running Codex: `node ~/.claude/plugins/cache/openai-codex/codex/1.0.6/scripts/codex-companion.mjs task --background [--write] --fresh --model <model> --effort <effort> "<prompt>"`, started from the worktree that owns the job; `status <job-id>` and `result <job-id>` only find jobs started from the same directory. The concurrency cap and the landing procedure are in `instructions/workflow.md`.
- The read-only sandbox cannot build Go or Rust. Run a code review with `--write` in a disposable copy of the worktree without `.git`, placed outside every Git working tree (the companion resolves its workspace with `git rev-parse --show-toplevel`), plus a `CHANGES.txt` holding the base commit, the tracked diff and the untracked files. Design reviews stay read-only.
- The sandbox has no network. Prefetch pinned crates (`cargo fetch` in a scratch project) and run `pnpm install` yourself before an implementer needs them, then tell it to work offline.
- Before writing a design document, read `docs/decisions.md` and `instructions/documentation.md`.
- Keep the scratchpad directory for temporary files; nothing temporary goes under `docs/`. Review output is saved there, and its findings become tasks in `TODO.md`.
