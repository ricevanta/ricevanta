# CI catalogue representation plan

Implement the [catalogue string representation spec](../specs/ci-contract-parsing.md) as one bounded data change with retained pure verification evidence. Both documents require approval by an independent `design_reviewer` before implementation. Follow [workflow](../../instructions/workflow.md) and [testing](../../instructions/testing.md); the coordinator owns Git, CI, integration and landing.

## Ownership and prerequisites

The implementer owns only eligible string-token spans in `scripts/ci/targets.toml` under `console-unit.tests`, plus a task-local verifier and evidence in the coordinator-assigned scratchpad. No production Python, test, workflow, schema, dependency, target meaning or deadline changes belong to this task. The verifier is not imported by production or added to CI. It is retained for independent review and replay, not installed as a new tool.

The designer owns these documents and the link from [CI hardening Task 3A](ci-hardening.md#task-3a-reuse-selected-inventory-within-one-cache-check). An independent `code_reviewer` reviews the final data diff and verifier, including the adversarial pass. Reviewers do not author fixes. Unknown failures go to a separately briefed troubleshooter. Concurrent writers use separate worktrees and preserve one another's work.

Consume the implemented Task 3A lifetime and CPython 3.14.8 under the [local proof input contract](../specs/ci-contract-parsing.md#4-paired-equality-proof). The coordinator freezes the local executable and actual `tomllib` identities; local proof does not require or claim native CI admission. The coordinator also supplies the frozen native profile report, its verifier, run URL, source identities and hashes. The report's policy parse count reflects three classification loads per complete check; it does not authorize eliminating other reads. No profile or full workload runs locally.

The coordinator establishes the exact content baseline. If the separate console inventory correction changes the same array, complete and review that content stage first, then apply this representation stage and repeat the complete proof. Do not use a fixed instance or distinct-name count as a gate. A pending content correction remains a separate blocker to final console qualification.

## Task 1. Pure verifier and controls

Owner: implementer, scratchpad only. Produce a standard-library verifier/converter with explicit original and candidate paths, a check-only mode, boundary controls and a nonzero exit for any failed condition. It may write a candidate only after all checks pass. The coordinator names the retained source/snapshot/report paths before work begins. Do not write repository files during this task.

- [ ] Read the specification, current `targets.toml`, `run_selected.load_targets`, `inventory.fuzz_targets`, raw-source consumers in `scripts/ci/test_*.py`, and pinned `tomllib` string parsing. Record the base identity and catalogue SHA-256 supplied by the coordinator; inspect encoding and line endings without executing helpers. Freeze the invoked/resolved local executable paths and hash, exact implementation/version and loaded `tomllib` package/module paths and hashes. Require byte equality of the package, parser and regex module sources with official CPython v3.14.8 and retain those source identities before any proof result is accepted.
- [ ] Implement only the supported source-span recognition and eligibility rules in spec sections 2 and 3. Parse the full original first. Decode candidates with `tomllib`, never a handwritten decoder. Refuse ambiguous target/array boundaries, unsupported rows, malformed input, CR source and a changed baseline hash before writing. Keep unchanged literals recognizable so a second transformation is byte-identical.
- [ ] Implement complete typed, ordered recursive equality and independent byte-span scope checks. Pair original/candidate raw snapshots under each existing reader form in the same identity-checked interpreter, with the same effective encoding on both sides. Record reader encoding and source hashes. Check executable and actual loaded module identities against the frozen values at invocation start and end; refuse missing or changed identities. Refuse unsupported parsed types. Preserve exact lists, duplicate occurrences, dictionary key order and all out-of-scope bytes.
- [ ] Add positive controls for ordinary printable ASCII, empty/space-only text, embedded double quotes, backslashes and a trailing backslash, escaped quotes/backslashes, ASCII Unicode escapes, one/two internal apostrophes and long nested JSON text containing literal backslash-n. Require token and full-document equality, including repeated identical pairs. Use synthetic small fixtures; no production test execution.
- [ ] Add refusal controls for decoded tab, LF, CR, CRLF, NUL, DEL, non-ASCII characters including Unicode line separators, quote-edge values and three-or-more apostrophe runs. Check escaped and unescaped forms where valid TOML permits them. Test malformed escapes, invalid Unicode scalar escapes, multiline basic tokens, malformed document structure and unsupported row syntax. Every valid refused token stays byte-identical; malformed/unsupported input produces no candidate file.
- [ ] Prove negative controls fail for the intended reason: delimiter-only replacement of escaped quotes/backslashes; literal backslash-u instead of decoded ASCII; changed newline or Unicode content; omitted duplicate; reordered pair; changed scalar type; reordered dictionary keys; and an out-of-scope byte edit. Separately demonstrate valid no-op and eligible conversions pass. Exercise idempotence. Report each control's expected and observed result without raw environment dumps.
- [ ] Run only syntax and the pure verifier controls using the frozen absolute local executable, for example `<absolute-python> -I -S -B -X pycache_prefix=<fresh-empty-scratchpad-directory> <scratchpad>/verify-ci-contract-parsing.py --self-test`. Record flags, actual module locations, source hashes, command and exit status. Use standard-library imports only, no repository helpers or Ricevanta imports, and no timing assertion. The fresh bytecode prefix prevents existing cached modules from replacing checked source. Do not claim payload/native admission or run bootstrap with an overridden host identity.

## Task 2. Representation-only candidate

Owner: implementer, the allowed `targets.toml` spans only. Consume Task 1's passing verifier and the coordinator's final content baseline. The representation-stage diff must contain no semantic inventory correction.

- [ ] Capture exact baseline bytes and SHA-256. Generate an in-memory candidate using decoded printable ASCII and the prescribed single/triple delimiters. Leave ineligible tokens byte-identical. Keep the largest eligible values in the normal path; never replace their full expectations with aliases or summaries.
- [ ] Run complete paired equality with both reader forms, typed ordering/multiplicity checks and byte-span checks before installing the candidate. Use Task 1's frozen local proof inputs, isolation flags and fresh bytecode prefix; recheck identities at invocation start and end and require the same effective encoding on both sides of each reader pair. Retain both raw snapshots, verifier source/hash and output. Report changed/refused counts as observations tied to these bytes. Do not compare with a stale golden model or merely a set of test names. This is a parsed-model proof, not timing or native qualification.
- [ ] Apply only the verified candidate. Reread the actual worktree file and require its SHA-256 and bytes to equal the candidate, then repeat the paired check against the retained baseline. Run the transformation again and require byte identity. Audit the diff for unchanged IDs, commands, headers, skips, budgets, comments, punctuation, line endings and all other target arrays.
- [ ] Inspect raw-source mutation fixtures for dependence on the rewritten spelling. Preserve existing tests and assertion counts. If a required fixture actually depends on an eligible token's old spelling, stop for a bounded design adjustment; do not silently weaken or rewrite the assertion. The final CI suite remains mandatory even when the static audit finds no dependency.
- [ ] Preserve every loader/read/parse boundary, handled exception, fail-before-load path and Task 3A lifetime by making no code change. Keep the 88 complete policy checks and every receipt mutation unchanged. Local validation remains syntax and pure representation checks; no `check_policy` run, helper suite, profile, mutation workload or timing loop belongs to this task.
- [ ] Supply the exact base/candidate identities, diff, retained verification paths and known limits to the coordinator. A concurrent content edit, rebase or conflict resolution invalidates the paired proof; regenerate from the resulting content baseline and rerun it before review.

## Task 3. Independent review and native qualification

Owner: coordinator for CI and evidence; independent `code_reviewer` for the data change, verifier and adversarial pass. Consume Tasks 1 and 2 evidence, the approved design and the final source identities.

- [ ] Review both the data diff and verifier independently. Check that the oracle parses both complete raw sources through the same reader, preserves recursive types/order/multiplicity, checks byte scope, and rejects false conversions. Inspect escaped quotes, backslashes, Unicode and quote-run boundaries, and ensure the verifier is not becoming an alternate runtime loader or authority.
- [ ] Confirm no production/test/workflow/schema/dependency changes, no new cache and no reduced parse/check/assertion counts. Preserve the independent console inventory correction's content evidence and exact full-instance accounting. Require fix confirmation from a reviewer who did not author the fix.
- [ ] Run normal exact-head CI with the unchanged 10-minute `ci-contracts` deadline and unchanged 30-minute bootstrap deadlines. Native bootstrap must execute the complete helper suite on Linux x64, Windows x64 and macOS ARM64, with all cold, corruption, foreign-identity, compiler and terminal-admission probes. Retain complete logs, actual discovered/executed counts, run URL, tested SHA, job durations and receipts. Reduced discovery, increased deadlines, omitted probes or a passing diagnostic selector do not qualify the change.
- [ ] Require unchanged policy and receipt mutation coverage, source freshness, unknown-ID refusals, missing/malformed catalogue failures, Python traceback retention and success-gated same-run receipt behavior. Run design/schema checks and all routed component work through normal CI. Tests remain unchanged and their actual results, not source inspection alone, establish compatibility.
- [ ] Require the final PR integration head's complete selected job set and `ci-required` to pass, with independent approval for that head. If the full deadline still fails, report it as failed and delegate new evidence-based diagnosis; no scope or timeout relaxation is implied. Do not claim a measured speedup from the representation proof or compare profiled and ordinary timings as equivalent workloads.

## Benefits, limits and completion evidence

The data-only scope avoids new runtime state and leaves fresh-read validation intact. The cost is mixed string syntax, conservative exclusions and an external proof artifact that must be replayed after source movement. Dependencies, alternatives and all seven attacker outcomes are owned by [spec section 6](../specs/ci-contract-parsing.md#6-trust-boundary-and-trade-offs); this plan introduces no additional mechanism or dependency.

Completion evidence contains approved design hashes, independent review and fix confirmations, the exact representation input/output pair, verifier source/hash and control results, unchanged contract audit, console content-stage evidence when applicable, and successful final-head native/required CI. A local pure check completes only its own step. No runtime or timeout improvement is an acceptance fact until the corresponding native evidence exists.
