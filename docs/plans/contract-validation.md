## Limits and review

Benefit: approved schemas and implemented harnesses cannot disappear from required work unnoticed. Cost: a small closed Python evidence mode and one pinned catalogue transition need maintained negative controls. Dependencies are the reviewed contracts, admitted Python/validator closure and exact CI route. No new library, registration, credential or vendor program is introduced. Task 4 measurements remain blocked on the agent core, release identity/build recipes and Linux build root; hosted fake-agent tests establish no full-agent budget, release baseline, sensor or platform support.

The CI trace remains candidate Git objects to admitted tools to validators/test evidence to same-run receipts to `ci-required`. A stolen enrollment token, compromised agent host, console session, extension publisher or database writer gains no CI credential or ability to select the catalogue exception. A network attacker can deny downloads but substituted tool bytes fail admission; a restored server gains no release or authority proof from a receipt. A malicious repository candidate can change its own tests and helper code, so independent review and branch controls remain necessary. No runtime attacker gate moves.

Rejected alternatives: an advisory OpenAPI step, exit-status-only unittest receipts, unqualified all-host skips, refreshing unseen source bytes, activating a half-synchronized catalogue, or treating fake-agent measurements as release evidence. Reviewer focus: exact migration pins and selector meanings, complete test discovery, actual native skip proof, default/source coverage separation, and preservation of every production gate.
