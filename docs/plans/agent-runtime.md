# Agent runtime implementation plan

Implement [the agent runtime spec](../specs/agent-runtime.md) in six tasks, each one pull request with failing tests first. The spec owns every contract; this plan owns order, paths, commands and proof. Nothing here authorizes enrollment, transport, sensors, IPC, spool files or the updater.

Roles: the coordinator owns dispatch, Git, CI evidence and landing; the implementer owns one task's paths; the independent code reviewer reviews each task and confirms fixes; the native OS crates and the service-manager glue need the adversarial pass. The designer does not implement or approve. Workers never commit or push. Follow [workflow](../../instructions/workflow.md) and [Rust instructions](../../instructions/rust.md); use separate worktrees for concurrent tasks.

## Boundaries and ordering

- Paths: `agent/Cargo.toml` members, `agent/Cargo.lock`, `agent/crates/{json,config,os,os-linux,os-macos,os-windows,core}/`, `schemas/agent/{json,config,health}/v1/` fixtures only through the designer, `.github/workflows/agent.yml`, `scripts/ci/targets.toml`, `scripts/ci/inventory.py`, `instructions/rust.md` and `instructions/testing.md` wording for the new crates, `server/AGENTS.md` untouched.
- Dependencies are exactly the pins the licensing rows name: `tokio =1.53.3`, `windows-sys =0.61.2`, `libc` at the version `Cargo.lock` already resolves. Every other crate is transitive through the lockfile. Adding anything else stops the task.
- Tasks 1 to 3 are portable and run on all three hosts. Task 4 runs native tests on macOS and Windows only. Task 5 needs Tasks 1 to 4. Task 6 needs Task 5 and [the footprint harness plan](footprint-harness.md) Task 3 for its measurement job.
- Local checks are formatting, Clippy and ordinary tests for touched crates; property budgets and native lifecycle tests run in CI. Commands run from `agent/` unless stated. `python` is the interpreter of `.github/python-version`.

Review focus: a configuration file or directory with wrong ownership or a permissive DACL that still loads (Tasks 2 and 4); a check made on a path rather than the opened descriptor or handle, or a Unix file created by resolving a checked directory's path again (Tasks 3 and 4); a signal that arrives before the runtime is built (Task 5); a stop request that returns from the SCM handler late or reports `SERVICE_STOPPED` twice (Task 5); a health document written non-atomically or world-writable (Task 5); an `unsafe` block without `expect` and `SAFETY` (Task 4); a sampler that allocates per call without bound (Tasks 3 and 4); a watchdog ping tied to a successful sample instead of a completed tick (Task 5); a configuration or directory open that blocks on a FIFO, or a created mode that depends on the umask (Tasks 3 and 4); a Windows end the SCM did not request that still reports `SERVICE_STOPPED`, or a requested stop that does not (Tasks 4 and 5); a restart rule that differs between the three managers (Task 5).

## Task 1. Strict JSON reader and writer

Owner: implementer. Own `agent/crates/json/`, the workspace member list and lockfile. Produces `ricevanta_json::{parse, Value, Error, encode}` with the strict profile of spec section 3: bounded input, depth, unique keys, `i64` integers only, canonical encoding with sorted keys and no whitespace.

- [ ] Write tests that load [`schemas/agent/json/v1/vectors.json`](../../schemas/agent/json/v1/vectors.json) and require every `accept` case to re-encode to `canonical_hex` and every `reject` case to return the named `Error` variant; match variants, not strings. Run `cargo test --locked -p ricevanta-json`; require red.
- [ ] Add a deterministic mutation test over the vectors with seed `0x52564a534f4e5631`, 20,000 cases, byte flips, truncation, duplication and depth growth; require no panic, termination and that every accepted mutant re-parses to an equal `Value`. Report seed, count and duration on `--nocapture`.
- [ ] Implement the reader and writer without `unsafe`, recursion depth bounded by a counter, no `unwrap` on input, and `Error` variants `Utf8`, `ByteOrderMark`, `TooLarge`, `TooDeep`, `DuplicateKey`, `Syntax`, `NumberFormat`, `NumberRange`, `Trailing`, `Surrogate`, `Control` with a byte offset.
- [ ] Run `cargo fmt --all -- --check`, `cargo clippy --locked -p ricevanta-json --all-targets -- -D warnings`, `cargo test --locked -p ricevanta-json` and `cargo tree --locked -p ricevanta-json --edges normal,build,dev`; require pass and no dependency.
- [ ] CI proof: `agent-unit` on all three hosts plus `json-extended` for the mutation run; the inventory lists both.

## Task 3. Portable traits and the Linux crate

Owner: implementer. Own `agent/crates/os/` and `agent/crates/os-linux/`. Produces the traits `ProcessSampler` (`fn sample(&self) -> Result<ProcessSample, SampleError>`), `ServiceManager` (`ready`, `status`, `watchdog`, `stopping`) and `Platform` (data root, default paths, footprint metric name, `open_config`, `open_parent`, `open_or_create_dir(parent, name)`, `create_file(dir, name, kind)`, `rename_in(dir, from, to)`, `remove_in(dir, name)`; nothing below a checked parent takes a path), and the Linux implementations: `/proc/self` readers, the `sd_notify` datagram client, and the descriptor-based checks and descriptor-relative creation of spec section 3.1 with `libc::O_NOFOLLOW | libc::O_CLOEXEC` and `libc::O_DIRECTORY` through `OpenOptionsExt::custom_flags` and `/proc/self/fd/<descriptor>/<name>`.

- [ ] Write tests with recorded `/proc` fixtures (a `stat` whose `comm` contains `) (` and spaces, a `smaps_rollup` with and without `Pss`, a `status` without `Threads`) and require correct parsing or `SampleError::Format`; a live test on Linux requires `threads >= 1`, `fd_count >= 3` and `footprint_bytes > 0` for the own process within 50 ms. A growth test in its own integration-test binary, with one test so nothing else allocates concurrently, takes 1,000 warm-up samples and then 10,000 more, and requires `Anonymous` in `/proc/self/smaps_rollup` to grow by at most 64 KiB (spec section 7). Code review checks the structural bound the spec states: fixed buffers of at most 4 KiB, no collection that grows with mappings, descriptors or threads, and one directory enumeration at a time.
- [ ] Write file-protection tests: a symbolic link at the configuration path fails with `ELOOP`; a configuration file with mode `0644` or `0640` fails and `0600` and `0400` pass; a foreign owner and a group-writable parent directory of the configuration file fail with the named reasons; a world-writable parent of the runtime directory (`0777`, and `1777` with the sticky bit) and a parent owned by another user fail; a root-owned parent with mode `0775` fails for the state and runtime directories and passes for the log directory; after the runtime directory is checked, the test renames it away and puts a new directory at its path, and the next `health.json` and `agent.log` writes land in the checked directory under its new name, never at the path; a pre-existing non-empty directory with the right owner is never re-moded, and a pre-existing `health.json.tmp` owned by another user is refused without being truncated; a FIFO at the configuration path fails at once as not a regular file, with no writer attached and a test timeout of 1 s proving the open does not block; under umask `0077` a created runtime directory ends `0755` and a created health document `0644`, and under umask `0000` a created state directory ends `0700`; a directory with mode `0750` fails and `0700` passes; a symbolic link in place of a directory fails; a file replaced between open and check is judged by the opened descriptor, proven by swapping the path after the open in the test.
- [ ] Write notify tests: bind a `UnixDatagram` on a temporary path and on an abstract name, set `NOTIFY_SOCKET`, and require the exact datagrams `READY=1`, `STATUS=ready`, `WATCHDOG=1` and `STOPPING=1`; require no datagram and no error when the variable is absent; require `WATCHDOG_USEC` parsing, exactly one `WATCHDOG=1` per completed tick, and no `WATCHDOG=1` when `WATCHDOG_PID` names another pid.
- [ ] Implement with the standard library plus `libc` constants (`O_NOFOLLOW`, `O_CLOEXEC`, `O_DIRECTORY`, `O_NONBLOCK`) and the workspace `forbid(unsafe_code)` inherited; set created modes with `File::set_permissions`; divide tick counts by the `USER_HZ` constant 100.
- [ ] Run `cargo fmt --all -- --check`, `cargo clippy --locked -p ricevanta-os -p ricevanta-os-linux --all-targets -- -D warnings` and `cargo test --locked -p ricevanta-os -p ricevanta-os-linux`; require pass on Linux and compile-only on the other hosts.
- [ ] CI proof: `agent-unit` on Linux with the live sampler, protection and notify tests named in the receipt.

## Task 4. Native crates for macOS and Windows

Owner: implementer; adversarial review required. Own `agent/crates/os-macos/` and `agent/crates/os-windows/`. Produces the sampler and descriptor checks on both, and on Windows the SCM dispatcher, control handler, status reporter, `SHGetKnownFolderPath(FOLDERID_ProgramData)` resolution with `CoTaskMemFree`, the `GetSecurityInfo` owner and DACL check of spec section 3.1 and the event log writer of spec section 6, under the lint rules of spec section 1.1.

- [ ] Add a repository check in `scripts/ci/check_policy.py` (coordinated with its owner) that every `unsafe` keyword under `agent/crates/os-macos` and `agent/crates/os-windows` sits in a function annotated `#[expect(unsafe_code, reason = ...)]` preceded by a `// SAFETY:` comment, that no `extern` block exists under `agent/`, and that no other crate under `agent/` contains the `unsafe` keyword. Require red against a fixture crate that violates each rule.
- [ ] macOS tests: the own process yields `footprint_bytes > 0`, `threads >= 1`, `fd_count >= 3`; `size_of::<libc::rusage_info_v4>() == 296` (16 bytes of `ri_uuid` plus 35 `uint64_t` fields); an invalid pid returns `SampleError::Os`; `mach_timebase_info` conversion agrees with `std::time::Instant` over a busy loop within 5 %; the Unix file-protection tests of Task 3, including the rename-away test, pass against the macOS implementation, which uses `openat`, `mkdirat`, `renameat` and `unlinkat`; the growth test of Task 3 passes with `ri_phys_footprint` as the measure.
- [ ] Windows sampler tests: the own process yields `PrivateWorkingSetSize > 0`, `handle_count > 0`, `threads >= 1`; a zero `PrivateWorkingSetSize` is reported as `SampleError::Unsupported`; `windows-sys` 0.61.2 provides `PROCESS_MEMORY_COUNTERS_EX2` and `GetProcessMemoryInfo` under `Win32_System_ProcessStatus`, so no struct is declared in the crate; the growth test of Task 3 passes with `PrivateUsage` as the measure.
- [ ] Windows protection tests, run as the runner's administrator: a tree prepared with `icacls <root> /inheritance:r /grant "*S-1-5-18:(OI)(CI)F" /grant "*S-1-5-32-544:(OI)(CI)F"` and `icacls <root> /setowner "*S-1-5-32-544" /T` passes; a tree whose root additionally grants `*S-1-5-32-545:(OI)(CI)M` (Users, modify) fails with `insecure_acl` naming `S-1-5-32-545`; a tree whose owner is set explicitly to the runner user with `icacls <object> /setowner "%USERNAME%"` fails on ownership (set explicitly, because an elevated administrator's new objects may default to the Administrators owner); an inherit-only `Users:(OI)(CI)(IO)W` entry on the log directory fails; the DACL evaluator, a function over decoded entries (type, flags, mask, SID), fails closed on synthetic `ACCESS_ALLOWED_OBJECT_ACE_TYPE` and callback entries; a `CREATOR OWNER` write ACE fails; a reparse point (junction) at any of the five objects fails; a null DACL fails; a configured state directory whose parent grants `Users:(OI)(CI)M` fails on the parent; a junction planted as `health.json.tmp` by an administrator is refused as a reparse point; the runtime directory with `Users:(OI)(CI)RX` fails like every other object, as do `Users:(S)` (synchronize only) on the state directory and `Users:R` on the configuration file, while an explicit `Users:(DENY)(W)` entry passes. The event log writer registers source `RicevantaAgent`, writes one `startup_failed` line whose `%` characters arrive as `\u0025`, and the test reads it back from the Application log with `Get-WinEvent`. The SCM glue is tested through a fake dispatcher trait here and through the real SCM in Task 5: a requested stop reports `SERVICE_STOPPED` exactly once, with `NO_ERROR` in time and `ERROR_SERVICE_SPECIFIC_ERROR` code 1 when late; a panic, configuration error or startup failure in `ServiceMain` ends the process with neither a `SERVICE_STOP_PENDING` nor a `SERVICE_STOPPED` report, the last reported state being `SERVICE_RUNNING` or `SERVICE_START_PENDING`.
- [ ] Implement with `[lints.rust] unsafe_code = "deny"`, `missing_docs = "deny"`, `#[expect]` per function, `// SAFETY:` comments, no public raw types, `libc` on macOS and `windows-sys` on Windows with the features the licensing row names.
- [ ] Run on the native host: `cargo fmt --all -- --check`, `cargo clippy --locked -p ricevanta-os-macos --all-targets -- -D warnings` or the Windows crate, and `cargo test --locked -p <crate>`; require pass. `cargo tree --locked -p <crate> --edges normal,build,dev` must list only the licensed closure, and `cargo tree -e features` output is attached to the pull request to confirm the licensing row's feature union.

## Task 5. Core binary, lifecycle and service managers

Owner: implementer; adversarial review required. Own `agent/crates/core/` (package `ricevanta-core`, binary `ricevanta-agent`). Produces the command line, lifecycle, logging, health document, stop sources and service-manager glue of spec sections 2 to 7.

Log event catalogue, the contract tests match: `agent_starting`, `config_default`, `config_loaded`, `directories_verified`, `dev_directories_created`, `log_opened`, `log_rotated`, `sampler_started`, `ready`, `sampler_failed`, `health_write_failed`, `watchdog_notify_failed`, `signal_ignored`, `stop_requested`, `task_panicked`, `shutdown_complete`, `shutdown_timeout`, `exit_delayed`, `startup_failed`.

- [ ] Write black-box tests that spawn the built binary: `--version` prints one line with the local identity and touches no file; `version --json` validates against the identity fields; `check-config` exits 2 on each invalid fixture with the pointer on stderr; `run` with a temporary tree reaches `state: ready` in `health.json`, the document validates against [`health.schema.json`](../../schemas/agent/health/v1/health.schema.json), `health` exits 0, a stale document (mtime moved back) makes `health` exit 1; `SIGTERM` (Unix) or `CTRL_BREAK_EVENT` (Windows, own process group) produces `stop_requested`, `shutdown_complete`, `state: stopped` and exit 0 within the deadline; a second signal during stop is ignored; a configuration directory with mode `0777` exits 3; a log over `max_file_bytes` rotates with `log_rotated` first in the new file; every log line is valid JSON under 8,192 bytes with the fixed keys. Require red before the binary exists.
- [ ] Add in-process tests of the lifecycle library with injected `ProcessSampler`, `ServiceManager` and task fakes, because a `cfg(test)` item exists only in the test harness and never in the binary a black-box test spawns: a sampler that always fails keeps the lifecycle running, sets `sampler_failed` and still calls `watchdog()` once per tick; a task that blocks past the deadline yields `shutdown_timeout`, `state: stopped` and exit code 1 within the deadline plus 1 s; a health writer that fails while running increments `health_write_failures` and sets `health_write_failed` without stopping, and one that fails during startup yields exit 3 at step `health_write`; under the macOS platform fake a startup failure returns its code no earlier than 10 s after start and at once on a stop request. No build of the binary carries a test hook.
- [ ] Implement the runtime: explicit `tokio` builder with two workers and four blocking threads, named threads, panic capture at task boundaries, directories verified before the file sink opens, atomic health writes, the rotation rules, `option_env!` identity, the stop sources per mode and the per-source deadline caps (15,000 ms on `SERVICE_CONTROL_SHUTDOWN`, 4,000 ms on `ctrl_close`).
- [ ] Default-parent evidence in CI: on each runner, record owner, group and mode (Unix) or owner and DACL (Windows) of every default parent and data root (`/etc`, `/var/lib`, `/run`, `/var/log`; `/Library/Application Support`, `/Library/Logs`; `<ProgramData>`), require that each passes spec section 3.1's parent rule, and report the evidence to the designer, which settles the verify marker on group-writable log roots.
- [ ] Linux service test in CI, under the system manager (hosted runners have passwordless `sudo`): start `sudo systemd-run --unit=rv-agent-test-$GITHUB_RUN_ID --wait --property=Type=notify --property=NotifyAccess=main --property=Restart=on-failure --property=RestartSec=1s --property=StartLimitIntervalSec=0 --property=TimeoutStopSec=20 --property=RuntimeDirectory=ricevanta-test --property=RuntimeDirectoryPreserve=yes -- <binary> service --config <profile>` in the background, with `RestartSec` shortened to keep CI fast and every other property as in spec section 5.2; `<profile>` is a copy owned by root with mode `0600` in a root-owned directory of mode `0755`, as spec section 3.1 requires. While the unit is active, read `NRestarts`, `MainPID` and `ActiveState` with `systemctl show` and require `NRestarts=0`, because systemd-run unloads a unit that ran successfully as soon as it ends. Then `sudo systemctl stop` it and require `systemd-run`'s exit status 0, its printed summary with the main process's exit status 0, and the final `state: stopped` document in the preserved runtime directory. Repeat the section 5.1 rows: `systemctl kill --signal=SIGTERM` ends the unit with exit 0 and no restart; `systemctl kill --signal=SIGKILL` yields a new `MainPID` and `NRestarts=1`; a configuration file with mode `0644` yields exit 3 and a growing `NRestarts` while the unit retries, after which `systemctl stop` and `systemctl reset-failed` clean up. The datagram sequence itself is Task 3's unit test.
- [ ] Windows service test in CI: prepare the tree with the `icacls` grants of Task 4 and place the profile in it as `agent.json`; `sc.exe create RicevantaAgentTest binpath= "<binary> service --config <profile>" type= own start= demand obj= LocalSystem`; set recovery with `sc.exe failure RicevantaAgentTest reset= 86400 actions= restart/10000` and `sc.exe failureflag RicevantaAgentTest 0`, and record the `sc.exe qfailure` and `sc.exe qfailureflag` output as evidence of the spec section 5.4 syntax. `sc.exe start` with a 100 ms interval profile and poll `sc.exe queryex` to `RUNNING`; require `health.json` ready. An elevated test process then opens `health.json` without `FILE_SHARE_DELETE` for 2 s: require `health_write_failures` to grow and `health_write_failed` to appear once the handle closes, with the service still `RUNNING`, and record whether the rename failed as spec section 3.1 expects. `sc.exe stop`, require `STOPPED` within 20 s with exit code 0 and no new process after 15 s. Start again, end the process with `taskkill /F /PID <pid>`, and require `RUNNING` with a new PID within 20 s. Replace the tree with a Users-writable one and require that each attempt leaves a `startup_failed` event with exit code 3 from source `RicevantaAgent` in the Application log, that the service never shows `STOPPED` with a service-specific exit code, and that the SCM starts it again about 10 s after each attempt. Finally `sc.exe config RicevantaAgentTest start= disabled`, `sc.exe stop`, `sc.exe delete`. The restart after a reported non-crash failure is not exercised, because the flag stays false by design.
- [ ] macOS service test in CI: place the profile as a root-owned `0600` file in a root-owned `0755` directory, write a temporary plist with the spec's keys under a test label, then `sudo chown root:wheel` and `sudo chmod 0600` it, because Apple requires a system daemon's plist to be owned by root and writable by no group or other user (spec section 5.3); `sudo launchctl bootstrap system <plist>`, poll `launchctl print system/<label>` for a pid and `health.json` ready. Measure the stop with `sudo launchctl kill SIGTERM system/<label>`, which launchctl documents as sending the signal: require `state: stopped` without `shutdown_timeout` in the final health document, the elapsed time within `shutdown.timeout_ms`, and no new pid for 15 s, since `SuccessfulExit` false does not restart a zero exit. Start it with `sudo launchctl kickstart system/<label>`, then `sudo launchctl kill SIGKILL system/<label>` and require a new pid within 15 s, which settles the verify marker for `SIGKILL`. If no new pid appears, switch the test plist to the `KeepAlive` true fallback of spec section 5.3, rerun, and require a new pid after both `SIGKILL` and a completed external `SIGTERM`; report the evidence to the coordinator, who records the fallback as the shipped plist through the designer. Replace the configuration with a mode `0644` file and require exit 3, each failed process living at least 10 s, and a new pid per attempt. Finish with `sudo launchctl bootout system/<label>`, require no process left, and record the observed `bootout` stop timing against `ExitTimeOut` as observed behaviour for the designer.
- [ ] Run `cargo fmt --all -- --check`, `cargo clippy --locked -p ricevanta-core --all-targets -- -D warnings`, `cargo test --locked -p ricevanta-core` and `cargo build --locked --release --target <host target> --bin ricevanta-agent`; require pass and a binary that prints `--version`.
- [ ] CI proof: `agent-unit`, `agent-lifecycle-linux`, `agent-lifecycle-windows`, `agent-lifecycle-macos` with the test names in the receipts; `check_policy` green; both reviewers' reports attached.

## Acceptance

The slice is complete when the binary starts, reports ready, samples itself, stops within its bound and exits 0 under all three service managers on hosted CI, with every contract test named in receipts and both reviewers' approvals for Tasks 4 and 5. It establishes no enrollment, transport, sensor, IPC, spool or update capability and no platform qualification; those remain the gates named in the spec's section 9.
