# Footprint harness implementation plan

Implement [the footprint harness spec](../specs/footprint-harness.md) in bounded tasks with failing tests first. The spec owns metrics, phases, checks, budgets and the baseline protocol; this plan owns order, paths, commands and proof, and it is the single home of the CI job, its leaf IDs and the build command the job runs.

Roles: the coordinator owns dispatch, Git, CI evidence and landing; the implementer owns one task's paths; the independent code reviewer reviews each task and confirms fixes. The designer does not implement or approve. Workers never commit or push. Follow [workflow](../../instructions/workflow.md) and [testing](../../instructions/testing.md).

## Boundaries and ordering

- Paths: `tests/footprint/` (`measure.py`, `check.py`, `samplers/{linux,darwin,windows}.py`, `profiles/idle.json`, `profiles/health-burst.json`, `budgets.json`, `baselines/`, `fake_agent.py`, `windows_io.py`, `test_*.py`), the `agent-footprint` job in `.github/workflows/agent.yml`, `scripts/ci/targets.toml`, `scripts/ci/inventory.py`, `scripts/ci/check_policy.py` for the agent-change rule, `instructions/testing.md` command labels. Schema fixtures under `schemas/agent/footprint/v1/` change only through the designer.
- The interpreter is the release in `.github/python-version` (3.14.8). `measure.py`, `check.py`, `fake_agent.py`, `windows_io.py` and the samplers import the standard library only; `test_measure.py` also imports `jsonschema` from the hash-locked validator closure of [CI hardening](../specs/ci-hardening.md) section 8, which the `footprint-unit` job installs on each native host with that section's command and no other `pip` package. Local runs use any interpreter of that release with the same closure.
- Tasks 1 to 3 run against `fake_agent.py`, a Python stand-in that writes a conforming health document and answers `version --json`, so they land before the agent binary exists. Their `footprint-unit` leaves and Task 4 need [CI hardening plan](ci-hardening.md) Task 6, which moves every workflow, including the native agent matrix, to `.github/python-version`; until it lands those hosts run another Python release and these leaves are not wired. Task 4 also needs [agent runtime plan](agent-runtime.md) Task 5 for the binary and [release plan](release-builds.md) Task 1 for `scripts/release/version.py`, which produces the identity file the job passes as `--identity`. Before wiring `footprint-linux-x64`, Task 4 also requires [release plan](release-builds.md) Task 4A, whose build root produces the Linux agent on `ubuntu-26.04` with the `linux-x64-ubuntu26.04` rows.
- Local checks are the unit tests and a `--duration-scale 0.1` smoke run; full phases run in CI only.

Review focus: a sampler that reads the wrong process after a pid reuse (Task 1); percentiles computed before warm-up removal (Task 2); evidence that claims an identity the binary does not report (Task 2); a missing baseline that passes on a tag build, a `pr` baseline accepted, or a mismatched environment that passes (Task 3); a `smoke` record accepted as baseline (Task 3); a `budgets.json` or baseline edit that lands without the stated reason or outside the follow-up procedure, or an environment change that keeps a stale baseline (Task 4); a tolerance hard-coded in `check.py` (Task 3); health writes that hide a stopped sampler, pre-phase samples, fabricated catch-up counts or warm-up-only rotations (Tasks 2 and 3).

## Task 1. Samplers

Owner: implementer. Own `tests/footprint/samplers/` and `tests/footprint/test_samplers.py`. Produces `sample(pid) -> Sample` per OS with `footprint_bytes`, `footprint_metric`, `cpu_ns`, `threads`, `descriptors`, `descriptor_kind`, and `environment()` with the fields of spec section 2 including `os_version`, `os_release`, `memory_bytes`, `clk_tck` on Linux and `mach_timebase` on macOS.

- [ ] Write tests that start a Python child which allocates and touches 64 MiB, opens 20 files and starts 4 threads, then require `footprint_bytes >= 60 MiB`, `threads >= 5`, `descriptors >= 20`, `cpu_ns` increasing across two samples while the child spins; a dead pid raises `SamplerError`; on Linux `clk_tck` equals 100 and a `stat` line with `) (` in `comm` parses; on macOS `ctypes.sizeof(rusage_info_v4) == 296` (16 bytes of `ri_uuid` plus 35 `uint64_t` fields) and the libraries are loaded from `/usr/lib/libproc.dylib` and `/usr/lib/libSystem.B.dylib`; on Windows the `PROCESS_MEMORY_COUNTERS_EX2` size is checked before the call and a zero `PrivateWorkingSetSize` raises `SamplerError`; `os_version` yields the per-OS key of spec section 6 and `memory_bytes` is positive. Run `python -B -m unittest discover -s tests/footprint -p test_samplers.py -v`; require red.
- [ ] Implement the three samplers with `ctypes` by absolute library path on macOS, `WinDLL("kernel32", use_last_error=True)` on Windows and `/proc` reads on Linux, each with the documented access right and bounded buffers; a failed sample is a typed exception, never a zero value.
- [ ] Repeat the test command on the implementer's host; CI runs it on all three native hosts. Require pass on each.
- [ ] CI proof: `footprint-unit` on Linux x64, Windows x64 and macOS ARM64 with the test names in the receipts.

## Task 2. Measurement and evidence

- [x] Write tests that run `measure.py` against `fake_agent.py` with `--duration-scale 0.05`: the evidence validates against [`evidence.schema.json`](../../schemas/agent/footprint/v1/evidence.schema.json) through `jsonschema` in the test environment; both phases appear with the profile SHA-256 of the committed profile files; the agent receives a copy of each profile in the temporary tree, with mode `0600` on Unix; samples exclude the warm-up; `p95` is the nearest-rank value of a known synthetic series; `cpu_core_pct` for a child spinning one core is near 100; `smoke` is `true` and `identity` is `null` without `--identity` and also under a scale below 1; the fake agent's `version --json` output appears as `binary.reported_identity`, and with `--identity` the file's four fields appear as `identity`; a fake agent that never writes `ready` makes `measure.py` exit 1 with `not_ready` within 30 s scaled and write no evidence; a fake agent that ignores the stop request records a nonzero `exit_code` after the deadline; a footprint summary of 0 fails `footprint_nonzero`; the temporary tree is removed. Require red.
- [x] Add fake-agent modes for one successful sample followed by no ticks, fresh health rewrites with frozen sample timestamps/counters, old samples, wrong pid/interval, null process, counter reset, excessive catch-up, debug disabled, repeated log lines and rotations only during warm-up. Tests must assert the semantic failure, not only schema validity. A healthy full profile passes; shorter-than-interval smoke progress is recorded without becoming a gate.
- [x] Collect phase wall/monotonic boundaries, every-read freshness/progress summaries and pre-stop endpoint snapshots under spec section 3.1; retain the nearest external sample paired by sample time. Parse and deduplicate bounded log files, require first-line rotation markers, and record counts without log text. On Windows use delete-sharing handles for health and log reads and test concurrent atomic replacement/rotation while those readers run; the harness must not create the write failures it gates. Test intervening stale observations even when endpoints are fresh, boundary-only sampling, wall-clock reversal, polling gaps, sample/write ordering, and shutdown writes that must not replace the pre-stop evidence.
- [x] Implement phases, identity verification, health polling, stop delivery (`SIGTERM`; `CREATE_NEW_PROCESS_GROUP` and `GenerateConsoleCtrlEvent(CTRL_BREAK_EVENT)` on Windows), sampling at 1 s, summaries, the self-sample cross-check and the environment record; profiles must validate against the agent configuration schema in a test.
- [x] Run `python -B -m unittest discover -s tests/footprint -p test_measure.py -v`; require pass. Run `python -B scripts/ci/validate_contracts.py`; require pass unchanged.
- [ ] CI proof: `footprint-unit` on all three hosts.

## Task 3. Checks, baseline and verdicts

Owner: implementer. Own `tests/footprint/check.py`, `budgets.json`, `test_check.py`. `budgets.json` starts as a copy of the `budgets` object in [`example.json`](../../schemas/agent/footprint/v1/example.json); any later change states its reason in the pull request.

- [x] Write tests using synthetic evidence documents, one per row of spec section 4: every check passes and fails at its boundary; `cpu_mean` in `idle` is `fail` above 5.0 and `recorded` otherwise with the 1.0 target beside it; `load` CPU is `recorded`; `self_sample_agreement` requires a valid fresh same-metric pair and then fails only when both the ratio and byte tolerance are exceeded; `identity_mismatch` fails when `binary.reported_identity` differs from `identity` in any one field, passes when equal and is `recorded` on a smoke record; thread and descriptor regressions fail only beyond the `threads`, `descriptors_fd` and `descriptors_handle` tolerances read from `budgets.json` (2, 4 and 16 in the seed), and changing a tolerance in a test copy of `budgets.json` moves the boundary, proving `check.py` holds no constant of its own; a missing baseline with channel `master` or `pr` yields `baseline_present` `recorded`, enforces absolute budgets and passes; every passing non-smoke `master` or `prerelease` run writes `baseline-candidate.json` byte-identical to the `--out` document, with or without an existing baseline, and a `pr` run, a smoke run or a failed run writes none; a missing baseline with candidate channel `prerelease` fails; a baseline with `identity.channel` `pr`, `smoke: true` or `outcome: fail` fails `baseline_invalid`; a baseline with another `runner_label` or `os_version` fails `baseline_environment`; footprint regression fails at 10 % and 2 MiB both exceeded and passes when only one is; a `budgets.json` that fails the schema's `budgets` definition exits 2; exit codes 0, 1 and 2 as specified. - [x] Consume every `expected_checks` case in [`schema-cases.json`](../../schemas/agent/footprint/v1/schema-cases.json): validate each instance's shape, then require the named semantic outcome. Reject results that claim pass without the supporting counters/timestamps and recompute agreement from the recorded external pair. - [x] Implement `check.py --evidence PATH --budgets PATH --baseline PATH [--out PATH]`, which treats an absent baseline path per the rules above, writes the completed evidence with `results`, `baseline` and `outcome`, writes `baseline-candidate.json` beside it when the run qualifies, and prints one line per result.

- [ ] Add routing and policy fixtures: an agent change without the footprint IDs is rejected; a workflow that passes `--duration-scale` in CI is rejected; a workflow that omits `--identity` is rejected. Run `python -B -m unittest discover -s scripts/ci -p 'test_*.py' -v`; require red, then green.
- [ ] Wire the job as a three-row matrix over `ubuntu-26.04`, `windows-2025` and `macos-26`, the release agent runners, with Linux using the admitted platform identity `linux-x64-ubuntu26.04` and with the target as a matrix constant: derive the identity with `scripts/release/version.py --root . --channel <validated channel> --ref <validated ref> --out "$RUNNER_TEMP/identity"`; pass its `rust-env.json` values only to recipe children, never workflow environment writers; build with `cargo build --locked --release --target "$RICEVANTA_TARGET" --bin ricevanta-agent` from `agent/` (the release recipe command, with fresh caches under the CI hardening rules), which on Linux runs inside the [Linux build root](../specs/linux-build-root.md#4-building-in-the-root) through `scripts/release/build_root.py build --unit agent`, followed by its mandatory per-binary ABI/map checks and distribution probes before measurement; then run `python -B tests/footprint/measure.py --binary "$RICEVANTA_AGENT_BIN" --target "$RICEVANTA_TARGET" --phases idle,load --identity "$RUNNER_TEMP/identity/identity.json" --out "$RUNNER_TEMP/footprint/evidence.json"` and `python -B tests/footprint/check.py --evidence "$RUNNER_TEMP/footprint/evidence.json" --budgets tests/footprint/budgets.json --baseline "tests/footprint/baselines/$RICEVANTA_TARGET.json" --out "$RUNNER_TEMP/footprint/result.json"`; upload the directory as 30-day evidence, also on failure. - [ ] Land the job without baseline files: branch and master runs pass on absolute budgets as spec section 6 step 3 allows, and master runs upload their candidates, so `ci-required` is green throughout. After each `release-ready` tag run the same procedure replaces the files with the tag run's candidates. A pull request that changes a runner label or another measured environment field deletes the affected baseline file in the same change (spec section 6 step 6).
- [ ] Hand the separate permission coverage-refresh owner the `qualification` baseline-promotion exemption from spec section 6 and both new spec paths for source inventory review. Require the reviewed regeneration procedure and default/source validator results; this task does not silently refresh digests or weaken provenance.
- [ ] Run `python -B scripts/ci/check_policy.py --root .`, `actionlint .github/workflows/*.yml` and `git diff --check`; require pass. Label the commands in `instructions/testing.md`.
- [ ] CI proof: the three footprint leaves green on master before and after the baselines land, `ci-required` green, and the release plan's Task 4 requirement for these leaves satisfied by the same receipts.

## Acceptance

The harness is complete when the three leaves produce schema-valid evidence for the agent core on every agent build, with fresh phase-relative samples, interval-consistent successful-sample progress, observed load debug events and rotation, budgets from the design, baselines landed through the follow-up procedure and no third-party dependency. It measures the core on hosted runners only; sensors, kernel memory, power and real-machine behaviour stay with the self-hosted gate of `design/agent.md` section 7 and [platform qualification](../specs/platform-qualification.md) section 7.
