## 2. Source-backed measurement defects

`processCPU` reads `/proc/self/stat`, parses user/system counters and multiplies by 10 ms. Linux defines those counters in ticks scaled by `_SC_CLK_TCK`, not nanoseconds ([proc_pid_stat](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html)). The diagnostic host's `CLK_TCK=100` makes 10 ms correct there; conversion does not recover sub-tick work. Dividing by 32 produces the observed 312,500 ns steps, not 312,500 ns measurement resolution.

The loop reads a separate counter for preflight end and decode start, and another for each next preflight start. CPU between those reads is omitted. A monotone synthetic counter can advance only in those gaps while both reported phase sums remain zero. Independently rounding each phase also loses the remainder when dividing by `N × repeats`. Increasing repetitions would not repair the gaps and is not selected.

On a `/proc` read/parse failure, the helper silently switches to runtime CPU estimates. Go 1.27.1 explicitly says its [CPU-class metrics](https://github.com/golang/go/blob/go1.27.1/src/runtime/metrics/description.go) are not directly comparable with OS CPU time. Switching counter domains between endpoints has no valid subtraction. `os.ReadFile`, string conversion and `strings.Fields` also perform measurement-only file/parsing work inside this memory test. Removing that work is justified by the timer replacement, but its contribution to a failed memory peak is unproved.

Go's [memory-limit API](https://github.com/golang/go/blob/go1.27.1/src/runtime/debug/garbage.go) counts total runtime memory minus released heap. The [class definitions](https://github.com/golang/go/blob/go1.27.1/src/runtime/metrics/description.go) include unreleased free heap, stacks and metadata. The [metric reader](https://github.com/golang/go/blob/go1.27.1/src/runtime/metrics.go) initializes its subsystem before the scalar baseline snapshot. The [GC guide](https://go.dev/doc/gc-guide#Memory_limit) supplies no fixed 1.1 guarantee. The current evidence demonstrates no subtraction error, missing class or baseline initialization flaw that authorizes a memory correction.

## 3. CPU counter and boundary contract

For Linux qualification use `syscall.Getrusage(syscall.RUSAGE_SELF, &usage)`. It returns process-wide user/system CPU across all threads, so the measurement includes workers and GC ([getrusage](https://man7.org/linux/man-pages/man2/getrusage.2.html)). The pinned Go wrappers call the kernel directly on [amd64](https://github.com/golang/go/blob/go1.27.1/src/syscall/zsyscall_linux_amd64.go) and [arm64](https://github.com/golang/go/blob/go1.27.1/src/syscall/zsyscall_linux_arm64.go). Use only `Utime` and `Stime`, checked seconds/microseconds conversion, and their sum. Reject syscall errors, negative seconds, microseconds outside 0 through 999,999, overflow or decreasing counters. No fallback, invented positive value or zero-cost substitution is allowed.

Linux [getrusage source](https://github.com/torvalds/linux/blob/v6.17/kernel/sys.c) obtains thread-group CPU and converts each component to a timeval; the [conversion](https://github.com/torvalds/linux/blob/v6.17/kernel/time/time.c) truncates nanoseconds to microseconds. Add a conservative 2,000 ns endpoint-conversion guard to the complete interval for acceptance. This bounds representation truncation, not scheduler-accounting accuracy or the physical CPU clock. Record the actual kernel/configuration; do not claim the upstream version proves every distribution's accounting. A zero complete interval remains invalid even with the guard.

The helper uses caller-owned fixed storage, performs no file reads, parsing, logging, heap growth or setup work before baseline, and has no new dependency. Keep the existing initial GC, scalar baseline, `baseline + N × weight` limit and post-baseline request boundary. Allocate the bounded CPU sample storage after baseline; include it in measured memory. Preserve the 1 ms scalar memory sampler, synchronous memory samples, request goroutines, fixture bytes, codec options, fresh per-request state, clearing and forced-GC policy. No class observer is added to normal qualification.

Let `R` be exactly 32 when declared size is at most 128 KiB or there is no codec entry, otherwise 1; let `q = N × R`. Retain exactly `2R + 1` counter pairs in fixed storage for at most 65 pairs of signed 64-bit user/system nanoseconds. No warm-up or adaptive repetition is allowed. Use this contiguous sequence:

1. `b0`: at the existing first CPU-read location before first preflight workers.
2. `b(2i+1)`: immediately after iteration `i`'s preflight workers join, before decode/refusal handling.
3. `b(2i+2)`: at the existing decode-end read after checks, memory sample, clearing and any forced GC. Reuse this boundary as the next iteration's start instead of reading again.

For combined counter values `b`, compute raw totals `P = sum(b(2i+1) - b(2i))`, `D = sum(b(2i+2) - b(2i+1))` and `T = b(2R) - b0`. Require nonnegative phase increments, `P + D = T`, and `T > 0`. Thus boundary bookkeeping and all work between phases remain inside the complete interval. The first/last counter call's own boundary effects are not a calibrated subtraction; interior counter overhead stays included. Keep the wall timer's existing scope and divisions.

The acceptance check is exact checked integer arithmetic: `(T + 2000) × 64 MiB <= 5,000,000,000 × paid_charge × q`. Use checked multiplication or arbitrary precision in parent-side validation, outside measurement. Overflow is an error, never saturation or wraparound. This retains the `5 seconds × paid_charge / 64 MiB` ceiling and is conservative about endpoint conversion. It does not exempt reference children or error paths.

Keep existing summary field names: `cpu_ns = floor(T/q)`, `preflight_cpu_ns = floor(P/q)`, `decode_cpu_ns = cpu_ns - preflight_cpu_ns`, and `cpu_ms = floor(cpu_ns/1,000,000)`. Decode's displayed average includes the final division remainder; it is not independently rounded. Raw totals and the guarded inequality are authoritative. Individual phases may be zero; combined zero fails. Reject any summary inconsistent with its raw ledger.

## 4. Retained evidence and validation

After the measured interval and sampler shutdown, emit one `COST_CPU_SAMPLE` record per boundary with exactly `case`, `mode`, `index`, `user_ns`, `system_ns`, in ascending index order. Values are nonnegative base-10 integers; case/mode must match the corresponding child. Then emit exactly one `COST_CPU` record with exactly `case`, `mode`, `source=linux-getrusage`, `samples`, `preflight_total_ns`, `decode_total_ns`, `total_ns`, `guard_ns=2000`. Use the existing unquoted whitespace-separated `key=value` grammar, rejecting duplicate, unknown, empty or malformed fields. Emit no diagnostic CPU record inside timing.

The Go parent requires the complete ledger and summary for both limited and reference children; it checks exact `R`, `q`, count, contiguous indices, nondecreasing user/system counters, totals, guarded bound and agreement with the existing `COST_MEASUREMENT` or `COST_REFERENCE`. Reject missing/duplicate or cross-case/mode records, out-of-range integers, changed source/guard and nonmonotone counters. Forward every validated limited ledger through the selected test's attributed output before its measurement record, so the wrapper can inspect it. Retain complete raw child output before reporting any validation failure, including syscall failures and the exact rejected values. Store kernel, architecture, toolchain and fixture/source identities with the run artifact. No JSON schema is introduced; these log records extend the existing cost-test evidence grammar.

The selected-test wrapper requires one validated CPU ledger for each attributed limited measurement using the same rules and exact 50 keys. This prevents an old successful child record without CPU provenance from satisfying the new contract. Reference validation remains the Go parent's responsibility. Preserve existing `COST_MEASUREMENT` fields, case keys, total, benchmark phase, same-run receipt identity and log retention. The wrapper may validate the integer contract itself; it must not accept a child assertion as raw provenance. `verified.json` carries `summary.cpu_protocol = linux-getrusage-v1`; the verified-record reader rejects its absence or another value, including stale evidence with otherwise correct case counts. CI policy pins this protocol and its wrapper enforcement.

Normal non-Linux package builds retain a stub returning an explicit unsupported qualification-clock error when the full cost test is requested. They never synthesize CPU or silently skip a requested full test. Existing ordinary-suite skip rules remain unchanged. Server deployment targets are Linux amd64/arm64; this library gate does not qualify endpoint macOS ARM64, Windows x64 or Linux x64. ARM64 and page-size evidence remain required before integration.

## 5. Scope, stop rule and permitted conclusions

The next slice changes only test CPU measurement, parent/wrapper validation and their focused tests. It makes no production admission or body change, moves no work before baseline and changes no memory formula, threshold, repetitions, corpus, window/output ceiling, CPU ceiling or wall rule. No second diagnostic population is authorized. The completed population's evidence and original failures remain retained.

After independent implementation review, run normal CI once on the candidate head with the unchanged full 50-case limited/reference obligation and separate three-iteration benchmark. Do not rerun an unchanged failing head to seek a pass. Preserve every failure. A positive short CPU record establishes measurement validity for that run, not a repair of the missing numeric badid failure. A new zero, counter error, overflow or ledger mismatch blocks the timer correction and returns its exact values to design. A valid CPU excess returns actual cost to design with the complete ledger; it cannot be resolved by more repetitions or a larger charge.

A memory excess remains a memory/model blocker. The timer change removes each CPU read's `os.ReadFile` buffer and parsing path; those temporary values carry no request data out of the helper, but their heap backing and runtime effects can outlive its return until collection. An implementation audit must use pinned source and compiler escape evidence to distinguish actual heap allocation from optimized conversions, enumerate removed operations/lifetimes and added fixed ledger storage, and confirm that the replacement counter does not retain state or allocate per read. This source-proven change is a justified machinery correction, not proof that its allocations caused either scalar excess.

After the complete normal 50-case proof and benchmark pass, the designer and independent reviewer may accept **current-candidate memory qualification** if that audit is complete, the baseline/limit and request/GC/sampling lifecycle remain unchanged, every memory value is unadjusted, and no unexplained setup or retention change moves cost outside the interval. The disposition must identify the corrective source diff, tested head, full proof and allocation audit, and retain both scalar failures as valid observations with exact causal composition unproved. This accepts the corrected measurement contract on its qualified host; it does not label those failures false, prove the timer caused them or establish a production memory repair. An unchanged rerun or a pass without the audited machinery change is ineligible. Missing audit evidence or a reviewer finding of unexplained state movement keeps the gate blocked.

If a corrected scalar child breaches 1.1, retain its complete CPU ledger and scalar memory values, report the exact case/host and source allocation audit, and return the request charge/runtime model to designer and independent review. The counter correction may stand as a separately verified measurement fix, but memory qualification and handler integration stay blocked. No additional population, class observer, baseline/charge/GC adjustment or production change is authorized here; a further task must pose a source-backed falsifiable question and receive its own design/plan approval.

## 6. Benefits, trade-offs, dependencies and alternatives

Benefits: process-wide CPU includes GC, contiguous boundaries cannot lose inter-phase work, raw evidence distinguishes zero resolution from malformed arithmetic, and no counter-domain fallback can corrupt subtraction. Replacing file/parsing measurement work also removes a known source of harness allocations without changing production behavior.

Trade-offs: syscall and ledger overhead remain charged; the 2 microsecond conversion guard can conservatively fail a boundary case. Fixed CPU storage slightly changes measured runtime state and may affect memory; no cross-run baseline equality or memory correction is inferred. Per-phase averages are diagnostic labels, while exact total cost decides acceptance.

Dependencies and limits: Go 1.27.1 and its standard library only, existing Linux CI hosts and required run artifacts. No vendor program, account, service or package is added. Linux kernel source is a behavior reference, not copied or linked GPL code. OS accounting is sampled, not a physical-cycle proof; the CPU protocol fixes representational and interval defects, not every host's scheduler behavior. The memory model remains unresolved.

Alternatives: longer/adaptive repeats or a zero waiver are rejected because they hide invalid measurement; `/proc` with corrected tick conversion still lacks short-path precision; Go CPU estimates are a different domain; wall time includes scheduling delays; `CLOCK_PROCESS_CPUTIME_ID` has finer representation but needs a new syscall/unsafe adapter where the existing standard-library `Getrusage` suffices. Raising C, rebaselining, preallocating receive buffers or changing GC policy is unsupported by the completed memory experiment.

## 7. Authority and unresolved questions

This is development-only evidence machinery. The [admission threat trace](ingest-admission.md#8-threat-trace) continues to govern the end-to-end path from authenticated device through receive/decode charge, release, refusal and retry. A stolen enrollment token or compromised agent gets no changed upload authority; a compromised console cannot change these test constants; a rogue publisher gains no upload path; a network intermediary gains no authentication; a database-only writer gains no limiter control; a restored server gains no persistent ticket or bypass of recovery sealing. No test artifact grants storage or acknowledgement authority. Endpoint classification and policy-redacted snippet limits are unchanged.

Which exact source operations and lifetimes explain the retained scalar memory excesses? What numeric CPU cost caused the retained badid breach? Does the corrected, guarded CPU ledger qualify the complete normal corpus on the candidate head? These remain evidence questions, not permission to relax the contract.
