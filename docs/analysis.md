# Requirements analysis

Where the blueprint collides with platform realities or with itself, what depends on what, and what is still unspecified. Decisions that resolve a conflict are in `decisions.md` (IDs such as `AG-01`). Support facts are in `platform-support.md`; license facts in `licensing.md`. Claims marked "verify" rest on vendor or forum sources rather than first-party documentation.

## 1. Conflicts

### C1. Vendor programs break "no external cloud" for the agent

The control plane is self-hosted, but Apple MDM delivery uses Apple's push service, and each deployment needs its own Apple MDM Push Certificate whose signing request the project signs with its MDM vendor certificate: a project-operated signing step at setup and at yearly renewal, the one dependency on the project that a self-hoster cannot remove. Chrome's content-analysis connector policies are `cloud_only`, so the strong browser gate on Chrome needs Chrome Enterprise Core, a Google-hosted dependency the operator accepts per deployment or forgoes for the content-script gate. Endpoint Security and Network Extensions need Apple-granted entitlements tied to a developer team. Windows driver distribution needs the submission accounts and production signature; ELAM needs Microsoft Virus Initiative membership. Self-builders need their own applicable grants and signatures for complete sensor support. Details and primary sources are in `platform-support.md`, vendor programs. Resolved by PF-03 and MDM-08.

### C2. The native MDM channel is mandatory

On macOS, the required managed profiles, DDM, OS update management, remote lock and erase, activation lock management and FileVault escrow use Apple's management channel. The modern macOS baseline uses DDM for update management and qualifies the exact declarations on each eligible release. On Windows, an on-premises OMA-DM server works without Entra ID through MS-MDE2 discovery and the Provisioning CSP; Autopilot needs Entra. On Linux the agent is the whole MDM. Resolved by MDM-01, MDM-03, MDM-05 and MDM-07.

### C3. Blocking without kernel code

| Channel | macOS (Endpoint Security) | Windows user mode | Windows driver | Linux (fanotify, BPF LSM) |
|---|---|---|---|---|
| Block process execution | Yes | No | Yes, process-creation callback | Yes, BPF LSM `bprm_check_security` |
| Block file open | Yes | No | Yes | Yes, `FAN_OPEN_PERM` |
| Block write, rename, copy to destination | Yes | No | Yes | BPF LSM; fanotify has no write-permission event |
| Block removable media mount | Yes | Device install policy | Yes | udev, BPF LSM `sb_mount` |
| Block network connection | Network Extension | WFP user mode | Yes | BPF cgroup and LSM hooks |

ETW is telemetry only. Fanotify permission groups need CAP_SYS_ADMIN. BPF LSM needs build support and activation in the running kernel's LSM list; version and successful program attachment do not prove that a hook runs. The installer triggers each required denial probe before completing preflight. Resolved by AG-01 and PF-02; runtime checks are in `platform-support.md`.

### C4. Memory target vs content inspection

The 80 MB idle target holds for the core runtime, not with YARA-X rules, a Magika model, document parsers and a CEL evaluator resident. Apache Tika is Java and cannot run in the agent. Resolved by AG-02.

### C5. Browser and clipboard channels need mediation in their own context

- Clipboard: blocking needs a decision before the first read and every later read. Windows delayed rendering publishes a reusable handle after the first render; macOS promised data has no documented per-read authorization hook. X11 and the Wayland owner candidates can receive selection requests, but watcher-then-re-own does not contain a read before ownership transfers. The contracts and required mechanism blockers are in `design/dlp.md` section 6.5; a measured re-own interval cannot qualify blocking.
- Browser transfers: Chrome's `webRequest` blocking callback is synchronous and `asyncBlocking` applies only to `onAuthRequired`, so an extension cannot hold an upload for a native-messaging scan there. Chrome, Edge and Firefox instead offer a local content-analysis agent interface (`content_analysis_sdk`; Firefox's `ContentAnalysis` policy) that holds uploads, pasted text, printing and downloads until the agent answers; Chrome's policies are `cloud_only` and Edge's exist on Windows and macOS only, and Safari has no such hook, so those cases rest on content-script interception, the weakest gate. Which hook a browser offers on which OS is declared in its browser adapter (EXT-06), so these facts live in data rather than in the agent.
- Cloud sync clients: observable as writes into known sync folders, a file-system channel.
- Email, messaging, AirDrop: not observable without app-specific integration.

DLP-01 defines the required contract; unresolved mechanisms remain release blockers under `design/dlp.md` sections 6.4 and 6.5. `specs/platform-qualification.md` defines the proof obligations, including bypass tests.

### C6. VPN gateways do not pass EAP-TLS from their own clients

- FortiGate SSL VPN (FortiOS 7.4.1+): the gateway validates the certificate and sends RADIUS a user name from a SAN field (UPN, email, DNS). FortiOS 7.6.3 removes SSL VPN tunnel mode on all models in favour of IPsec VPN, so from 7.6.3 FortiClient connects over IKEv2, where certificate-derived RADIUS authorization through `mfa-mode subject-identity` is unconfirmed (verify).
- FortiGate IKEv2: EAP passes through to RADIUS, but FortiClient initiates only EAP-MSCHAPv2 and EAP-TTLS; EAP-TLS is documented with the Windows native IKEv2 client. RadSec is required in FIPS mode.
- Cisco ASA with Secure Client: certificate authentication is local to the ASA; RADIUS authorizes with a user name from certificate DN attributes. EAP-TLS pass-through from Secure Client is not documented (verify).

RADIUS therefore sees only the user name the gateway extracted. Binding that name to the certificate needs unique per-device SAN values, RadSec mutual TLS, per-gateway secrets, and rejection of names without an issued, unrevoked certificate. Resolved by RAD-01.

### C7. Sigma rules do not target OCSF

Sigma rules declare Sysmon or Windows Event Log logsources and field names. Evaluating them needs a field map per logsource and the matching telemetry: event IDs 4688, 4624, 7045, registry, PowerShell script blocks, Sysmon-equivalent network and image-load events. Falco rules need a second map. Resolved by EDR-01.

### C8. Two CEL runtimes

Server policies evaluate in `cel-go`; agent policies in Rust (the `cel` crate, which ships the cel-spec conformance harness with an ignored-test list; or `cel-cxx`, which wraps cel-cpp through a C++ build chain). Divergence means a policy passes on the server and fails on an endpoint. Resolved by SH-02 and POL-01.

### C9. PostgreSQL alone vs telemetry volume

Raw process, file and network telemetry is 10^4 to 10^5 events per endpoint per day; 1,000 endpoints produce 10^7 to 10^8 rows per day. PostgreSQL with partitioning holds detections and bounded context, not raw telemetry at that rate. Resolved by EV-01.

### C10. Hardware-backed keys constrain TLS and enrollment

Secure Enclave keys are P-256 and non-exportable; TPM and CNG keys are reached through platform APIs. mTLS from Rust needs a TLS stack that delegates signing to a platform key (`rustls` with a per-platform `SigningKey`, or the platform TLS stack). SCEP commonly assumes RSA. Resolved by PKI-01.

### C11. Roadmap ordering

Enrollment (v0.1.x) needs a minimal CA before the full PKI milestone (v0.3.x). EDR and DLP need the policy and event contracts from v0.1.x, before adapter completion in v0.8.x. Native MDM and browser extension milestones are explicit in `roadmap.md`. Resolved by SH-02 and the roadmap.

### C12. Linux is many platforms

Distribution maintenance, the running kernel and active enforcement hooks, package managers, init systems, filesystems and mount layout, X11 versus Wayland, desktop versus server. A named maintained release is eligible, but support needs the exact configuration and behavioral evidence. Resolved by PF-02 and PF-04.

## 2. Dependency order

```
OCSF profile ──────────────┐
Policy envelope + CEL profile ─┤
Agent runtime + OS adapters ───┼─> Enrollment + device identity (minimal CA)
                               │        ├─> MDM agent ──> Apple MDM server, Windows OMA-DM server
                               │        ├─> PKI (CA, ACME, SCEP) ──> RADIUS ──> VPN profiles
                               │        ├─> EDR telemetry ──> Sigma adapter ──> response actions
                               │        │        └─> Lineage (stable file and process identities)
                               │        ├─> DLP classification (scanner helper) ──> DLP enforcement
                               │        │        └─> Lineage classification inheritance
                               │        └─> Event export ──> SIEM adapters
```

Lineage needs the stable file and process identities of `design/lineage.md` section 2 from both EDR and DLP before it can be built.

## 3. Missing specifications

These contracts and unresolved fields block implementation of their consumers. Settle each design, publish its machine-readable contract and add positive and negative fixtures before implementing validation, generated types or interoperability.

- Authority recovery and audit: `specs/authority-journal-protocol.md` proposes typed records, publication and sealed restore, but does not establish cross-store ordering. A submitted head update or external effect can complete after PostgreSQL releases its timed-out lock. Implementation remains blocked first on an independent cross-store gate or recipient fence and its proof, then on exact typed records, the full audit payload and replay model, deterministic authority-domain reducers and dependency closure, signed external-action evidence, database DDL and grants, a model-checked transition system and crash fixtures (`design/backend.md` section 6.1, BE-12). The candidate does not change key custody or make the journal ready.
- Shared signing: `server/internal/signing/dsse` implements [the DSSE spec](specs/dsse-envelope.md) (SH-05) and executes the shared vectors in `../schemas/dsse/v1/`. Certificate trust, replay and recovery remain consumer duties; unnamed journal, audit, custodian and project-release payload types and publisher fingerprint contracts remain open in the spec.
- Identity: OIDC claim and directory attribute mapping; user-to-device binding on shared devices.
- MDM: the per-kind `Baseline` item schemas and the `SoftwarePackage` and `DeviceGroup` schemas under `schemas/policy/v1alpha1/`; revision-bound item evidence, required-set and grace-episode schemas; and the typed records and qualification in `specs/mdm-evidence-recovery.md`. Command-query evidence has a candidate replay boundary, while unsolicited Apple status still needs measured snapshot and delivery evidence. Windows route retirement needs the candidate's destructive partial-state proof and a jobs-only acknowledgement key that `api` cannot use. Linux needs all-path exclusion across compare-delete or an atomic primitive because another writer can reuse a numeric slot. The current TLS listener boundary cannot qualify FileVault: an exposed `device` role can acknowledge and discard the rotated-key body, so FileVault needs an Apple protocol guarantee or a response-path trust-boundary redesign (`specs/baseline.md`, `design/mdm.md` sections 9.1 and 12). The signing service's hosting, availability target and abuse handling under the company remains open (PF-03).
- Enforcement release blockers: `specs/endpoint-mechanism-research.md` records candidates and qualification tests without native results. Windows minifilter, Linux FUSE and macOS FSKit staging still need exact-byte and existing-reference proof, and FSKit passthrough supplies no macOS 15 candidate. Clipboard first-read and repeated-read mediation remains a gap. Safari needs exact-transfer mediation including established WebSocket sessions; Chrome without Chrome Enterprise Core and Edge on Linux need established WebSocket and WebTransport mediation (`design/dlp.md` sections 6.4 and 6.5). Quarantine needs race-safe native identity exclusion and recovery. macOS identity-bound termination still lacks a public supported primitive, and operator-script descendant containment remains unresolved (`specs/edr-response-actions.md` sections 3.1, 3.2 and 3.7).
- Lineage: native incarnation continuity, deletion and identifier reuse across observation gaps, immutable revision capture on every supported filesystem, confidence calibration and revision-bound cross-device joins; durable sensitivity-floor transactions, safe floor compaction, signed approved reclassification and server-to-endpoint convergence; bounded graph compaction, candidate summaries and intermediate query expansion with pressure fixtures (`design/lineage.md`, LIN-01). The graph and budget contracts are defined; their mechanisms remain unqualified.
- PKI: remaining certificate-profile constraints (key usage, extended key usage, subject and SAN rules) and lifetimes and algorithms for profiles without settled defaults, OCSP response validity and failure behavior, CRL publication bounds for non-agent consumers, and external CA protocol. `design/pki.md` settles service certificates at 90 days, network-access certificates at 30 days with ECDSA P-256, and policy-signing certificates at 90 days with Ed25519; those defaults are not open. Network identities and renewal overlap are settled; generation-specific RADIUS evidence requires the binding and availability contract in `design/radius.md` section 6, not selection from those overlapping inventory rows.
- RADIUS: `specs/network-transition-qualification.md` defines candidate records and pure transitions for renewal overlap, accounting, session control and custody recovery. Certificate-profile fields, machine-readable records, positive and negative fixtures, gateway-specific stale-packet and actual-state evidence and compromise-recovery qualification remain open (`design/radius.md` sections 5 to 8, `specs/radius-gateway-profiles.md` sections 1 and 3.1). No runtime or gateway support is claimed.
- Agent spool: `agent/crates/spool` implements [the format spec](specs/agent-spool-format.md) as a file-free codec tested against the shared fixtures on all three targets (AG-10). Native durable sync, physical recovery and file ordering, counter persistence, epoch transitions, sealing/compression, upload and spool caps remain separate gates; format tests cannot qualify them.
- Agent batch writer: [the spec](specs/agent-batch-writer.md) and [plan](plans/agent-batch-writer.md) define the file-free second Rust slice (AG-11). Independent design approval, exact dependency/license closure and native codec tests gate implementation acceptance; measured active memory gates core integration. Durable file ordering, upload and retry remain separate work.
- Backend: the [permission catalogue](specs/permission-catalogue.md) defines names, scopes, approval metadata, schemas and fixtures under `schemas/permissions/v1/`; `server/internal/authz/catalogue` implements it as an isolated metadata library. Operation bindings, role evaluation and catalogue compatibility across restore remain consumer gates. Still missing: the test OIDC and SAML providers for end-to-end tests; the narrow acknowledgement-fence schema, serving-role grants and cross-replica and promotion crash fixtures (`design/events.md` section 3.5). `specs/core-primitives.md` fixes internal UUIDv7 and decoded batch-descriptor validation for the first Go slice. `specs/event-upload-wire.md` defines the descriptor header, skippable frame and response contract with fixtures under `schemas/events/v1/`; `server/internal/events/wire` decodes only the descriptor prefix. `server/internal/events/body` implements [the event batch body spec](specs/event-batch-body.md): bounded NDJSON decompression and preliminary binding, tested against the body fixtures (EV-09). Compiled OCSF decoding, device authentication, deduplication, storage, enrichment and acknowledgement remain separate gates.
- Extensions: the exact WIT interfaces per capability (`classifier`, `parser`, `collector`, `responder`) with their match, text, broker and row schemas; machine-readable schemas for `extension.respond` with the union of child permissions and approvals, durable step rows, collector disclosure profiles, browser registrations, digest-pinned console asset mounts, safe-operation catalogue, bridge bindings and bridge messages; the connector contracts (`export-destination`, `ca-connector`, `notifier`, `enricher`) with their timeouts, retry rules and immutable epoch/generation-bound CA callback admission, consumption and invalidation records; the `service` certificate profile; community adapter facts for Brave, Vivaldi, Opera, Arc and the Firefox forks (LibreWolf, Waterfox, Zen) (`design/extensions.md`, `specs/extension-agent-runtime.md`). `specs/isolation-qualification.md` is an unadopted single-capsule and isolated-worker candidate. The existing asset routes remain authoritative. A `WindowProxy`, emission receipt and handshake challenge do not bind the exact active document across navigation, so the capsule must stay disabled. Native path exclusion, literal memory enforcement and bounded cleanup also remain unproved.
- Policy: the matcher, report and adapter-pin schemas (`schemas/policy/v1alpha1/matcher.json`, `report.json`, `adapters.yaml`) with immutable pack/version/digest/rule identities; the global point/core conflict plan and dependency encoding; signed nonce-bound exception-time anchors, suspend-inclusive clocks and durable expired markers; pinned exact regex translation and compatibility fixtures; bounded SQL function catalogue and all-OS isolated worker launcher, sandbox, aggregate budgets and kill/reap protocol; Sigma placeholder resource placement; the `dedup` field for repeated findings (`design/policy.md`, `specs/policy-envelope.md`, `specs/rule-adapters.md`, `design/events.md` section 2.2). Missing machine contracts block consumers; prose bounds do not qualify a mechanism.
- Holds: the organization capture-gate functions, source catalogue, durable boundary, pins, tasks and receipts; fenced ClickHouse copy and retention recovery and the `lineage` interfaces. No hold may claim `active` until those contracts and interleaving fixtures prove complete capture (`design/events.md` section 5, EV-07).
- Reports and export: `schemas/report/v1alpha1/report-template.json` and `schemas/report/v1alpha1/catalogue.json` are absent. Encode the report fields and limits, type every source catalogue field, and bind current read permissions and immutable run footprints. [The ExportDestination schema spec](specs/export-destination-schema.md) and [plan](plans/export-destination-schema.md) define typed parameters, references and fixtures under `schemas/export/v1alpha1/` (EV-10), and `server/internal/events/exportdest` and the design CI validate them. S3 still needs the immutable plan, configuration revision, replay namespace, staged payload, manifest and verification receipt schemas with mismatch and recovery fixtures before delivery implementation (`specs/report-template.md`, `specs/event-export.md` section 10).
- Extension packages: the package manifest schema and fixtures under `schemas/extension/v1alpha1/` are defined in `specs/extension-manifest.md`, and `server/internal/extensions/manifest` implements the decoded validator; YAML and archive loading and stateful admission remain separate slices. `extension-resource.json`, `browser-adapter.json`, browser-registration and capability-grant schemas are absent. Encode global id ownership, publisher-key transfer, permanent immutable id/version tombstones, canonical targets, exclusive ownership, reserved namespaces, revocation and bounded values before implementing package admission or browser-policy writes. `schemas/wit/`, `schemas/console-bridge/v1/` and `schemas/openapi/connectors/<contract>/v1.yaml` are absent; settle exact types, versions, error responses, content-disclosure rules, operation exclusions and recovery-epoch bindings before implementing extension runtimes, console dispatch or connector clients.
- Event and rule contracts: `schemas/ocsf/extensions/ricevanta/` contains only `extension.json`; `dictionary.json`, custom `events/` and `objects/`, and `schemas/ocsf/compiled/` are absent. `schemas/ocsf/sigma-logsources.yaml`, `schemas/ocsf/falco-fields.yaml` and `schemas/policy/osquery-tables.yaml` are absent. Define all custom class and object fields, resolve platform coverage and unmapped reasons, pin upstream schemas, and validate emitted-event and translation fixtures before implementing ingest types or adapters (`specs/ocsf-profile.md`, `specs/rule-adapters.md`).
- CEL declarations: [the declaration spec](specs/cel-declarations.md), [loader plan](plans/cel-declarations.md) and `schemas/cel/v1/` define the versioned catalogue, schema and fixtures, and `server/internal/policy/celdecl` implements the declaration loader (POL-08). Compiler, editor and agent consumers still need source-schema bindings, closed-map and missing-binding proofs, exact-certificate access checks and serial/fingerprint formats. `schemas/ocsf/limits.yaml` lacks `match.categories`; reconcile the proposed 256-entry ceiling and its `match.regulations` entry before category compilation. The pinned cel-go API also requires version-specific confirmation.
- API and commands: `schemas/openapi/` and `schemas/commands/edr/` are absent. Settle operation IDs, scoped request/response types, action-specific parameters and error cases before generating console clients or implementing command admission (`architecture.md`, `specs/edr-response-actions.md`). The `RulePack`, `NetworkAccessProfile` and `RadiusGateway` resource schemas also lack files; settle their package, outcome-attribute and secret-reference constraints before GitOps or resource validators consume them.
