## Vendor programs and signing

The project holds the Apple developer team, granted sensor entitlements and Windows driver submission accounts for the distributed packages (PF-03). Each self-hosted Apple MDM service needs its own Apple MDM Push Certificate, obtained at identity.apple.com from a signing request the project signs with its MDM Vendor CSR Signing Certificate; the project operates that signing service, designed with the MDM server, the one project-hosted step a self-hoster cannot remove, used at setup and at yearly renewal. The service runs at `mdm-push.ricevanta.io`, verifies the requester's email, keeps only the request hash, organization, email and time, and never receives the push private key; an operator holding its own MDM Vendor CSR Signing Certificate can sign locally with `ricevanta mdm sign-push-request` instead (`design/mdm.md` section 9.4). The operator renews with the same Apple ID so the push topic and enrollments survive. The project's extension publisher key (Ed25519, held offline by maintainers) signs first-party extensions and the extension index; servers ship its public key on their trust list (`design/extensions.md` section 2).md` section 4) and the syslog structured-data ID `ocsf@<PEN>` (`specs/event-export.md` section 6). Self-builders need their own applicable grants and signatures to provide the complete feature set.

| Release | macOS app and nested executables use Developer ID Application signing, installer packages use Developer ID Installer, required entitlements and provisioning profiles are present, and distribution uses hardened runtime, notarization and stapling. The Windows driver passes HLK qualification and receives the production Microsoft signature through the project's WHCP submission (AG-01). The production push-certificate signing service runs under the company's MDM Vendor CSR Signing Certificate; a personal-account grant serves testing only. Apple Business Manager and Microsoft Virus Initiative are needed for the capabilities deferred to v2.0.0 (`platform-support.md`). |

Vendor requirements and primary sources are in `platform-support.md`. A signing approval is a prerequisite; the exact shipped package still needs functional and security qualification on every declared configuration.
